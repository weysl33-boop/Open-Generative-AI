## 0. 一句话结论

**中台的「表、页面、引擎」都已建成，但「运行链路」仍然跑在旧的单供应商旁路上。**
智能路由、计价引擎、9 个适配器、调用尝试、成本流水在生产代码中**零调用者**；
线上真实生成走 `models_config`（540 个模型、固定价、单供应商），且存在**不计费的裸代理**。

因此本次工作不是「新建中台」，而是「把已经建好的中台接上电」，
同时补上它缺的三块：目录完整性、异步任务续跑、对象存储。

### 3.1 六项致命断点

1. **智能路由未生效** —— 评分公式里 `success_rate` 无实测来源、`speedScore` 是常量 90/80、
   `capacity` 取自配置的 `concurrency_limit` 而非在途数；且 4 种模式里只有 `balanced` 读权重。
2. **Failover 不存在** —— `providerRuntime` 只对**同一供应商同一请求**重试 2 次；
   超时后会**重新发起一次计费的上游调用**，却只扣用户一次积分。
3. **异步任务永不续跑（对视频是致命的）** —— 供应商只回 requestId 时任务停在 `processing`，
   而 worker 只扫 `status='queued'`，唯一会碰它的是 15 分钟超时看门狗 → **必然判失败并退款**。
   叠加 `providerRuntime` 60s 硬超时 < 内联轮询设计值 180s，长任务连同步轮询都跑不完。
4. **成本/利润中心恒为 0** —— 读的是空表；`analyticsFinancial` 与 `pricingEngine` 用了
   两套互相矛盾的积分汇率（100 credits/USD vs ¥0.07/credit≈$0.0097/credit）。
5. **熔断器与自身 schema 冲突** —— `circuitBreaker.js:51` 写 `circuit_state='open'`，
   但 CHECK 只允许 `('closed','circuit_open','half_open')` → 触发即抛约束异常，**永不熔断**；
   `probeProviderChannel` 读 `probeResult.status` 而适配器返回 `healthy` → **所有探测一律降级**，
   健康页 `successRate24h` 由空表算出 → **展示假的 100%**。
6. **不计费的裸代理** —— `/api/api/v1/**`、`/api/app/**`、`/api/workflow/**`
   用平台密钥把任意路径转发到 `api.muapi.ai` 并**原样回传上游 JSON**，
   其中 `POST /api/api/v1/**` 不建任务、不冻结积分。

### 3.2 供应商分发的架构违规

`generationProviders.js` 是一个 360 行的 `if provider === ...` 级联：
缺密钥时**静默改用 MuAPI 的 key 并发给该供应商的域名**，
而 `lib/adapters/index.js:53` 的注释正声称杜绝此事（但那段代码里并无实现）；
`ModelsManagerClient.jsx:109,158` 甚至**在前端硬编码供应商路由**；
Seedream 5.0 遇 `ModelNotOpen` 自动降级 4.5 —— 属于需求明令禁止的跨模型降级。

适配器契约完成度：`createTask` 8/8、`getTask` 6/8、`healthCheck` 8/8（4 个是假的）、
`cancelTask` `estimateCost` `normalizeResult` `normalizeError` `handleWebhook` `getBalance` **全部 0/8**（基类空实现）。
Kling 用 `Bearer 裸key`（官方要求 AK+SK 签 JWT）、漏 `GroupId`、i2v 轮询打错路径 —— 一旦接通即 401。
火山/即梦在生产里真实在用，但**没有适配器、不在 `ai_providers`**。

## 4. 资金一致性

**做对的**：三桶钱包 + `FOR UPDATE` 行锁 + `bucket_split_json` 原路退回 +
`credit_reservations.idempotency_key UNIQUE` + `creations(user_id,idempotency_key)` 唯一 +
终态守卫的 commit/void；一个 Job 不可能扣两次，也不可能失败却不退款。这是全系统最扎实的部分。

**风险（按优先级）**：

| 级 | 问题 | 位置 |
|---|---|---|
| 高 | 冻结 TTL 15min < 真实视频耗时；成功回调晚于看门狗 → 已成功的生成被判失败并退款（供应商钱已花） | `constants.js:56` / `generationCore.js:376` |
| 高 | `commitCredits` 禁止部分结算：reserve 与 commit 之间管理员改价 → `SETTLEMENT_MISMATCH` → 成功任务回滚 | `creditService.js:316` |
| 高 | `transferCurrency` 读付款方钱包**未加行锁** → K-Coin 并发双花 | `currencyService.js:232` |
| 高 | 每日签到 TOCTOU：先查后锁，且 ledger 写 `idempotency_key=NULL`（被部分唯一索引排除）→ 并发白送积分 | `creditService.js:93` / `currencyService.js:382` |
| 高 | `CURRENCY.COIN_TO_CREDITS_RATE` **常量不存在** → `NaN` → 币换积分功能 100% 报错 | `exchangeService.js:23` |
| 中 | 无订阅积分月度发放任务；Stripe/微信/支付宝全部发放到 `perpetual`（永不过期），`subscription_credits` 只由币买 VIP 产生 → 「订阅积分周期失效」规则实际不成立 | `webhookDispatcher.js:52,202` |
| 中 | 过期只在读取时判定，没有清零；`users.credits` 镜像用裸求和，**多报已过期额度** | `creditService.js:16,249` |
| 中 | 无 Credit Lot / 按最早过期优先消费；无 per-lot 过期 | — |
| 中 | 账本不可变仅靠约定：无触发器、无 REVOKE、无 `balance_before` | `004` |

## 5. 前台 / 后台

**后台**：`app/admin/models/{providers,catalog,routing,pricing,health,cost-center,profit-center}` 全部真实读库，无假数据。
但存在**两个真相源**：`/admin/models` 与 `/admin/providers/models` 读写旧 `models_config`，
其余读写 `ai_studio.*`，两边改成本互不影响。
路由页缺并发/限速/熔断配置/拖拽排序；定价页**没有倍率与折扣编辑器**（选了公式计费也只能存 `base×{}`）。
成本/利润中心只有 7/14/30 天，缺今天/昨天/本月/自定义；利润页把估算金额直接显示成 `$X.XX`（违反「不要制造虚假精确金额」）。

**前台**：供应商概念**大量泄漏** —— `/api/models/active` 直接下发 `provider` 字段；
`VideoStudio.jsx:463-595` / `ImageStudio.jsx:904,1008,2584` 有「所有提供商」标签页、供应商 logo、
`provider_name` 展示；`providerLogos.js` 全部取自 `cdn.muapi.ai`；
BYOK 引导用户去 `muapi.ai/access_keys` 建密钥；`middleware.js` CSP 放行 `muapi.ai`。
这与需求 §1/§28 正面冲突。

**安全**：AES-256-GCM 密文存 `provider_secrets` ✅，但主密钥由 4 个 env **回退拼接**且 `key_version` 恒为 1
（换/缺 env 会静默不可解密，`getProviderSecret` 吞异常返回 null）；
`GoogleAdapter` 把 key 放 **URL query**；生成回调只有**全局单一共享密钥**、无逐供应商 HMAC、无时间戳防重放；
`alerting.js` 往外部 webhook 发未脱敏 `details`；`admin/system/logs` 权限常量拼错，静默降级为 `healthRead`。
历史泄露面：仓库内 tarball / `cookies.txt` / `支付宝密钥/` 均未入库（`.gitignore` 已覆盖），但**仍在工作树里**。

## 8. 需要用户拍板的商业规则

需求 §41 允许自动推进，以下三项影响真实收费，先说明默认取值（如不同意请指出）：

1. **切价策略**：回填时把 `models_config.credits_price` 原值写为 `fixed` 定价 → **上线当天用户价格零变化**。
2. **裸代理**：`/api/app`、`/api/workflow` 收为「上传/取URL/工作流定义」白名单，
   计费生成一律必须走统一 API；`POST /api/api/v1/**` 直接下线（已确认无调用方）。
3. **订阅积分过期**：现有 Stripe/支付宝/微信发放全部落在 `perpetual`。是否改为
   「订阅赠送到期清零 + 充值永久」？这会改变已付费用户的既有额度性质，属不可逆商业规则 —— **不擅自改，等确认**。
